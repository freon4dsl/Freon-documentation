# Customization Terminology

This glossary summarizes important terms and concepts introduced in the **Customization** section of the Freon documentation.

---

### General Concepts
- **Fre-tools** — The modular components generated by Freon, such as the editor, scoper, typer, validator, parser, and standard library.
- **Stacked Architecture** — Freon’s three-level structure for combining default, definition-based, and custom code.
- **FreonConfiguration** — Central class where all custom editors, actions, scopers, typers, and validators are registered.
- **Customization Level** — The layer where handwritten TypeScript code extends or replaces generated behavior.
- **Replacement** — Fully substituting a generated Fre-tool by implementing its interface (e.g., `FreScoper`, `FreTyper`).

---

### Editor Customization
- **Box Provider** — A generated class that produces boxes for specific AST concepts in the editor.
- **Custom Projection** — A user-defined method that returns a box for a given concept, registered in `nodeTypeToBoxMethod`.
- **Custom Action** — A user-defined editor action created with `FreCustomAction.create()`.
- **Box Type** — A visual building block in Freon’s editor framework.
- **Projection Priority** — Freon checks for custom, then definition-based, then default projections.
- **FreProjectionHandler** — Manages projection rendering and links between nodes and boxes.
- **Box Role** — An identifier linking actions to specific visual elements.

---

### External Components
- **External Component** — A Svelte or Svelte-wrapped component embedded inside a Freon projection.
- **Simple Addition** — An independent external component not linked to the model (`SimpleExternalBox`).
- **Wrapper** — A component that encloses an existing projection (`*WrapperBox`).
- **Replacer** — A component that replaces an existing projection (`*ReplacerBox`).
- **RenderComponent** — Freon’s internal renderer for displaying a `childBox` inside an external component.
- **FreComponentProps** — The props passed to an external component, containing `editor` and `box`.
- **Box API** — Key methods such as `findParam()`, `setFocus()`, and `refreshComponent()`.
- **Wiring** — The process of registering external components via `setCustomComponents()` in `src/starter.ts`.
- **Global Section** — The `.edit` file section listing available external components.

---

### Scoper Customization
- **FreScoper Interface** — Defines the logic for resolving references and names in a model.
- **Custom Scoper** — A user-defined replacement for the generated scoper (currently not per concept).
- **Environment Configuration** — The process of updating `YourLanguageNameEnvironment` to register a custom scoper.

---

### Typer Customization
- **FreTyper Interface** — Defines the logic for type inference and conformance.
- **Custom Typer** — A per-concept customization implemented in `CustomYourLanguageNameTyperPart.ts`.
- **FreType** — Represents a type instance within the model.
- **Custom Typing Method** — A user-defined method overriding type-related behavior, such as `conformsList()`.
- **Return Null Convention** — Returning `null` signals that Freon should fall back to generated typer logic.

---

### Other Customizations
- **FreReader Interface** — Defines how models are parsed from text.
- **FreWriter Interface** — Defines how models are serialized or exported.
- **FreStdlib Interface** — Defines all predefined instances and limited concepts for a language.
- **Singleton Pattern** — Ensures that only one instance of the standard library exists at runtime.
